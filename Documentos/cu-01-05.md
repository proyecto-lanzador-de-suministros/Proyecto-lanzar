# Casos de Uso - Gestión de Usuarios y Cuentas

## CU-01: Crear cuenta
* **Descripción:** Permite a remitentes o solicitantes crear su cuenta, sujeta a aprobación.
* **Actores:** Remitente, Solicitante
* **Precondiciones:** Ninguna (Registro inicial).
* **Postcondiciones:** La cuenta ha sido creada, pendiente de aprobación si se requiriera.

### Secuencia Normal
1. **Acción (Actor):** El usuario ingresa al panel de creación de la cuenta.
   * **Reacción (Sistema):** El sistema lista los campos a completar.
2. **Acción (Actor):** El usuario completa los campos.
   * **Reacción (Sistema):** El sistema valida la información y solicita confirmación.
3. **Acción (Actor):** El usuario confirma la creación de cuenta.
   * **Reacción (Sistema):** * **3.1** Si el usuario es solicitante, la cuenta se crea exitosamente.
     * **3.2** Si el usuario es remitente, la cuenta pasará a estar sujeta a aprobación (**CU-02**).

### Excepciones
* *No se registraron excepciones para este caso de uso.*

### Requisitos No Funcionales y Atributos
* **Rendimiento:** El sistema deberá realizar las acciones descritas en los pasos 1 al 2 en un máximo de 3 segundos, sin contar el tiempo de input del usuario.
* **Frecuencia:** Este caso de uso se espera que se lleve a cabo una vez por usuario.
* **Importancia:** Vital
* **Urgencia:** Hay presión
* **Comentarios:** -

## CU-02: Aprobar cuenta
* **Descripción:** Permite al administrador aprobar una cuenta registrada en el sistema para habilitar su uso. Esto aplica principalmente a cuentas de tipo remitente que requieren autorización de la organización antes de operar en el sistema.
* **Actores:** Administrador
* **Precondiciones:** 1. El usuario se registró en el sistema.
  2. La cuenta se encuentra en estado pendiente de aprobación.
  3. El administrador inició sesión en el sistema.
* **Postcondiciones:** 1. La cuenta queda en estado aprobada y puede utilizar el sistema según su rol.
  2. El sistema registra la aprobación.
  3. Se notifica al usuario que su cuenta fue aprobada.

### Secuencia Normal
1. **Acción (Actor):** El administrador accede al panel de administración.
   * **Reacción (Sistema):** El sistema muestra el panel con las cuentas pendientes de aprobación.
2. **Acción (Actor):** El administrador selecciona una cuenta pendiente.
   * **Reacción (Sistema):** El sistema mantiene la información disponible para revisión.
3. **Acción (Actor):** El administrador revisa los datos de la cuenta.
   * **Reacción (Sistema):** El sistema muestra la información del usuario (datos personales, rol solicitado, etc.).
4. **Acción (Actor):** El administrador presiona la opción "Aprobar cuenta".
   * **Reacción (Sistema):** El sistema valida la acción del administrador.
5. **Reacción (Sistema):** El sistema cambia el estado de la cuenta a Aprobada.
6. **Reacción (Sistema):** El sistema registra la aprobación en el sistema.
7. **Reacción (Sistema):** El sistema envía una notificación al usuario indicando que su cuenta fue aprobada.

### Excepciones
* **Caso A:** El administrador decide rechazar la cuenta.
  * **Reacción (Sistema):** El sistema cambia el estado de la cuenta a rechazada y notifica al usuario.
* **Caso B:** La cuenta ya había sido aprobada previamente.
  * **Reacción (Sistema):** El sistema informa al administrador que la cuenta ya se encuentra aprobada y no realiza cambios.
* **Caso C:** Ocurre un error al actualizar el estado de la cuenta.
  * **Reacción (Sistema):** El sistema informa al administrador del error y mantiene la cuenta en estado pendiente.

### Requisitos No Funcionales y Atributos
* **Rendimiento:** El sistema deberá realizar la acción descrita en el paso 4 al 7 en un máximo de 3 segundos.
* **Frecuencia:** Este caso de uso se espera que se lleve a cabo una media de 10 veces al día.
* **Importancia:** Vital
* **Urgencia:** Inmediatamente
* **Comentarios:** La aprobación es necesaria principalmente para habilitar remitentes, ya que forman parte de la organización y deben ser verificados por un administrador antes de operar en el sistema.

## CU-03: Cambiar info. login
* **Descripción:** Permite a remitentes o solicitantes cambiar la información requerida para iniciar sesión correctamente con su propia cuenta en la aplicación. Un administrador puede también realizar esto con cualquier cuenta dada.
* **Actores:** Remitente, Solicitante, Administrador (Admin)
* **Precondiciones:** La cuenta cuya información será modificada debe existir en el sistema.
* **Postcondiciones:** La información de inicio de sesión de la cuenta ha sido actualizada.

### Secuencia Normal
1. **Acción (Actor):** El usuario ingresa al panel de información de la cuenta.
   * **Reacción (Sistema):** El sistema lista la información de la cuenta.
2. **Acción (Actor):** El usuario solicita modificar la información de login.
   * **Reacción (Sistema):** El sistema muestra la opción solicitada, mostrando los campos a completar de la nueva información de login.
3. **Acción (Actor):** El usuario ingresa la nueva información de login, completando los campos requeridos.
   * **Reacción (Sistema):** El sistema solicita confirmación.
4. **Acción (Actor):** El usuario confirma los cambios.
   * **Reacción (Sistema):** El sistema muestra un mensaje confirmando que la información fue actualizada correctamente.

### Excepciones
* *No se registraron excepciones para este caso de uso.*

### Requisitos No Funcionales y Atributos
* **Rendimiento:** El sistema deberá realizar las acciones descritas en los pasos 1 al 4 en un máximo de 3 segundos, sin contar el tiempo de input del usuario.
* **Frecuencia:** Este caso de uso se espera que se lleve a cabo una media de una vez cada 6 meses, por usuario.
* **Importancia:** Importante
* **Urgencia:** Puede esperar
* **Comentarios:** -

## CU-05: Eliminar cuenta
* **Descripción:** Permite a un usuario (solicitante o remitente) eliminar su propia cuenta del sistema, o al administrador eliminar la cuenta de cualquier usuario. Una vez eliminada, el usuario no podrá volver a acceder al sistema.
* **Actores:** Solicitante, Remitente, Administrador
* **Precondiciones:** * El usuario debe haber iniciado sesión.
  * La cuenta a eliminar debe existir en el sistema.
* **Postcondiciones:** * La cuenta del usuario queda eliminada.
  * El usuario ya no puede iniciar sesión.

### Secuencia Normal
1. **Acción (Actor):** El usuario accede a la sección de configuración de su cuenta.
   * **Reacción (Sistema):** El sistema muestra la información de la cuenta y las opciones disponibles. 
   * *Nota:* Si el actor es administrador, el sistema deberá mostrar la lista de usuarios registrados para seleccionar la cuenta a eliminar.
2. **Acción (Actor):** El usuario selecciona la opción “Eliminar cuenta”.
   * **Reacción (Sistema):** El sistema solicita confirmación de la acción.
3. **Acción (Actor):** El usuario confirma la eliminación de la cuenta.
   * **Reacción (Sistema):** El sistema elimina la cuenta de usuario.
   * *Nota:* Si la cuenta posee solicitudes activas, el sistema deberá solicitar una confirmación adicional.
4. **Reacción (Sistema):** El sistema muestra un mensaje confirmando que la cuenta fue eliminada correctamente.
5. **Reacción (Sistema):** El sistema finaliza la sesión del usuario.

### Excepciones
* **1. La cuenta no existe:**
  * **Reacción (Sistema):** El sistema mostrará un mensaje indicando que el usuario no fue encontrado.
* **2. Error al conectarse con la base de datos:**
  * **Reacción (Sistema):** El sistema mostrará un mensaje de error y la operación será cancelada.

### Requisitos No Funcionales y Atributos
* **Rendimiento:** El sistema deberá realizar las acciones descritas en los pasos 2 al 4 en un máximo de 3 segundos.
* **Frecuencia:** Este caso de uso se espera que se lleve a cabo una media de 2 veces al mes.
* **Importancia:** Importante
* **Urgencia:** Puede esperar
* **Comentarios:** -
