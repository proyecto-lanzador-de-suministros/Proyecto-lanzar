## CU-16: Confirmar solicitud recibida
* **Descripción:** Permite al solicitante o al administrador confirmar que el paquete fue recibido correctamente, cambiando el estado de la solicitud a “Completada” y notificando al remitente.
* **Actores:** Solicitante, Administrador
* **Precondiciones:** * Debe existir una solicitud en estado “Lanzada”.
  * El usuario debe haber iniciado sesión con el rol de Solicitante o Administrador.
* **Postcondiciones:** * El estado de la solicitud cambia a “Completada”.
  * El Remitente recibe una notificación/solicitud de recepción.

### Secuencia Normal
1. **Acción (Actor):** El solicitante accede al detalle de su solicitud.
   * **Reacción (Sistema):** El sistema muestra la información y estado de la solicitud.
2. **Acción (Actor):** El solicitante selecciona la opción “Confirmar recepción”.
   * **Reacción (Sistema):** El sistema solicita confirmación de la acción.
   * *Nota:* **2.1** Si el administrador realiza la acción, el sistema deberá actualizar igualmente el estado de la solicitud y notificar al remitente.
3. **Acción (Actor):** El solicitante confirma la recepción del paquete.
   * **Reacción (Sistema):** El sistema actualiza el estado de la solicitud a “Completada”.
4. **Reacción (Sistema):** El sistema ejecuta el caso de uso **Notificar recepción de solicitud**.
5. **Reacción (Sistema):** El sistema muestra un mensaje confirmando que la solicitud fue registrada como recibida.

### Excepciones
* **Caso A: La solicitud no existe:**
  * **Reacción (Sistema):** El sistema mostrará un mensaje de error.
* **Caso B: La solicitud no esté en estado “Lanzada”:**
  * **Reacción (Sistema):** El sistema impedirá la confirmación e informará al usuario.

### Requisitos No Funcionales y Atributos
* **Rendimiento:** El sistema deberá actualizar el estado de la solicitud en un máximo de 3 segundos.
* **Frecuencia:** Este caso de uso se espera que se lleve a cabo una vez por cada solicitud completada.
* **Importancia:** Vital
* **Urgencia:** Inmediatamente
* **Comentarios:** -

## CU-17: Consultar Stock
* **Descripción:** Un remitente o admin visualiza el estado actual del stock de suministros de uno o más remitentes, pudiendo ver el detalle por tipo de suministro y el historial de actualizaciones. El admin puede consultar el stock de cualquier remitente; el remitente solo el propio.
* **Actores:** Remitente, Administrador
* **Precondiciones:** * El actor debe tener una sesión activa.
  * El remitente debe tener cuenta aprobada y activa.
  * Debe existir al menos un remitente registrado en el sistema.
* **Postcondiciones:** * El actor visualiza la información de stock solicitada.
  * No se realizan modificaciones en el sistema.

### Secuencia Normal
1. **Acción (Actor):** El actor accede a la sección de gestión de stock.
   * **Reacción (Sistema):** El sistema muestra el stock propio del remitente (o un selector de remitente si el actor es Administrador), desglosado por tipo de suministro con las cantidades actuales.

### Excepciones
* **Caso A: El remitente no tiene stock registrado aún:**
  * **Reacción (Sistema):** El sistema deberá mostrar todos los suministros en cero e indicar que no se han realizado actualizaciones de stock.

### Requisitos No Funcionales y Atributos
* **Rendimiento:** El sistema deberá cargar y mostrar el stock en un máximo de 3 segundos.
* **Frecuencia:** Se espera que se lleve a cabo una media de 2 a 5 veces por día por remitente.
* **Importancia:** Importante
* **Urgencia:** Hay presión
* **Comentarios:** Este caso de uso es de solo lectura y complementa al **CU-18 Actualizar Stock**. El stock se descuenta automáticamente al aprobarse una solicitud, por lo que el remitente puede usar esta consulta para saber cuándo es necesario hacer un restock.

## CU-18: Actualizar Stock
* **Descripción:** Un remitente o admin indica manualmente que realizó un reabastecimiento (restock) de suministros, actualización de la cantidad disponible en su stock personal dentro del sistema.
* **Actores:** Remitente, Administrador (Admin)
* **Precondiciones:** * El actor debe tener una sesión activa.
  * El remitente debe tener cuenta aprobada y activa.
  * El remitente debe haber realizado físicamente el restock antes de registrarlo.
* **Postcondiciones:** * El stock del remitente queda actualizado en el sistema con los nuevos valores.
  * El historial de actualizaciones de stock queda registrado.
  * Las próximas solicitudes considerarán el stock actualizado al realizar el control.

### Secuencia Normal
1. **Acción (Actor):** El actor accede a la sección de gestión de stock.
   * **Reacción (Sistema):** El sistema muestra el stock actual del remitente, desglosado por tipo de suministro.
2. **Acción (Actor):** El actor ingresa las nuevas cantidades actualizadas para cada tipo de suministro y confirma la actualización.
   * **Reacción (Sistema):** El sistema valida que los valores ingresados sean números positivos (**2.1**). Si son válidos, actualiza el stock del remitente, registra la fecha y hora del restock y muestra un mensaje de confirmación (**2.2**).

### Excepciones
* **Caso A: El actor ingrese valores no numéricos o negativos:**
  * **Reacción (Sistema):** El sistema deberá mostrar un mensaje de error indicando el campo inválido y solicitar corrección sin guardar cambios.

### Requisitos No Funcionales y Atributos
* **Rendimiento:** El sistema deberá realizar la actualización del stock (pasos 1 al 2) en un máximo de 3 segundos.
* **Frecuencia:** Se espera que se lleve a cabo una media de 1 a 5 veces por semana por remitente.
* **Importancia:** Vital
* **Urgencia:** Hay presión
* **Comentarios:** El stock se actualiza manualmente por el remitente. El sistema solo descuenta automáticamente al aprobarse una solicitud. Consulta pendiente: definir si el stock es global o individual por remitente (actualmente se asume individual).

## CU-19: Consultar Solicitudes Pendientes
* **Descripción:** Un remitente o administrador visualiza el listado de solicitudes que se encuentran en estado 'Aprobada' (sin remitente asignado aún) y que corresponden a la zona de cobertura del remitente. El administrador puede ver todas las pendientes para asignarlas manualmente.
* **Actores:** Remitente, Administrador
* **Precondiciones:** * El actor debe tener una sesión activa.
  * El remitente debe tener cuenta aprobada y activa.
  * Debe existir al menos un remitente registrado en el sistema.
* **Postcondiciones:** * El actor visualiza la lista de solicitudes pendientes filtrada según su rol.
  * No se realizan modificaciones en el sistema.

### Secuencia Normal
1. **Acción (Actor):** El actor accede a la sección 'Solicitudes pendientes'.
   * **Reacción (Sistema):** * **1.1** El sistema recupera las solicitudes en estado 'Aprobada'. Si el actor es Remitente, filtra solo las correspondientes a su zona de cobertura; si es Administrador, muestra todas.
     * **1.2** El sistema muestra el listado con información resumida de cada solicitud: identificador, zona/localidad, tipo y cantidad de suministros, fecha de creación y tiempo de espera.

### Excepciones
* **Caso A: No existen solicitudes pendientes:**
  * **Reacción (Sistema):** El sistema deberá mostrar un mensaje informativo indicando que no hay solicitudes disponibles por el momento.

### Requisitos No Funcionales y Atributos
* **Rendimiento:** El sistema deberá cargar y mostrar el listado de solicitudes pendientes en un máximo de 4 segundos.
* **Frecuencia:** Se espera que se lleve a cabo una media de 3 a 10 veces por día por remitente activo.
* **Importancia:** - *(No especificado)*
* **Urgencia:** - *(No especificado)*
* **Comentarios:** -

## CU-20: Consultar Estado de Solicitud
* **Descripción:** Un usuario autenticado (solicitante, remitente o admin) consulta el estado actual de una solicitud específica para conocer en qué etapa del proceso se encuentra y obtener información detallada sobre la misma.
* **Actores:** Solicitante, Remitente, Administrador
* **Precondiciones:** * El actor debe tener una sesión activa.
  * Debe existir al menos una solicitud registrada en el sistema.
  * El solicitante solo puede consultar sus propias solicitudes; el remitente las que tiene asignadas; el admin todas.
* **Postcondiciones:** El actor visualiza el estado actual y los datos relevantes de la solicitud consultada. No se realizan modificaciones en el sistema.

### Secuencia Normal
1. **Acción (Actor):** El actor accede a la sección 'Mis solicitudes' o 'Gestión de solicitudes'.
   * **Reacción (Sistema):** El sistema muestra el listado de solicitudes accesibles para el actor, con información resumida: identificador, fecha, estado actual.
2. **Acción (Actor):** El actor selecciona una solicitud específica para ver su detalle.
   * **Reacción (Sistema):** El sistema muestra el detalle completo de la solicitud: estado actual, historial de estados, zona de entrega, suministros solicitados, remitente asignado (si aplica), fechas estimadas y notificaciones enviadas.

### Excepciones
* **Caso A: El actor no tiene solicitudes registradas:**
  * **Reacción (Sistema):** El sistema deberá mostrar un mensaje informativo indicando que no hay solicitudes disponibles.

### Requisitos No Funcionales y Atributos
* **Rendimiento:** El sistema deberá cargar y mostrar el detalle de la solicitud en un máximo de 3 segundos.
* **Frecuencia:** Se espera que se lleve a cabo una media de 3 a 5 veces por solicitud activa.
* **Importancia:** Importante
* **Urgencia:** Hay presión
* **Comentarios:** Los posibles estados que puede mostrar son: Creada, Aprobada, Rechazada, Asignada, En Preparación, Listo, En Camino, Lanzada, Completada, Cancelada y Anulada. El mapa interactivo es relevante principalmente para los estados En Camino y Lanzada.
