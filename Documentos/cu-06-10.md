## CU-06: Iniciar sesión
* **Descripción:** Permite a un solicitante, remitente o administrador autenticarse en el sistema mediante sus credenciales para acceder al mismo.
* **Actores:** Solicitante, Remitente, Administrador
* **Precondiciones:** El usuario debe tener una cuenta registrada en el sistema.
* **Postcondiciones:** * El usuario accede al sistema con su rol correspondiente.
  * Se muestra el panel correspondiente al tipo de usuario.

### Secuencia Normal
1. **Acción (Actor):** El usuario accede a la pantalla de iniciar sesión.
   * **Reacción (Sistema):** El sistema muestra el formulario de login.
2. **Acción (Actor):** El usuario ingresa su nombre de usuario y contraseña.
   * **Reacción (Sistema):** El sistema valida las credenciales, identifica al tipo de usuario (solicitante, remitente o administrador), inicia la sesión y muestra el panel correspondiente.
   * *Nota:* **2.1** Si las credenciales son incorrectas, el sistema deberá mostrar un mensaje de error y permitir volver a intentarlo.

### Excepciones
* **1. El usuario está eliminado:**
  * **Reacción (Sistema):** El sistema mostrará un mensaje indicando que la cuenta no está habilitada.
* **2. Fallo en el sistema de autenticación:**
  * **Reacción (Sistema):** El sistema mostrará un mensaje de error e impedirá el acceso.

### Requisitos No Funcionales y Atributos
* **Rendimiento:** El sistema deberá validar las credenciales en un máximo de 2 segundos.
* **Frecuencia:** Este caso de uso se espera que se lleve a cabo una media de 50 veces al día.
* **Importancia:** Vital
* **Urgencia:** Inmediatamente
* **Comentarios:** -

## CU-07: Cerrar Sesión
* **Descripción:** Un usuario autenticado (solicitante, remitente o admin) decide finalizar su sesión activa en el sistema. El sistema invalida la sesión y redirige al usuario a la pantalla de inicio.
* **Actores:** Solicitante, Remitente, Administrador
* **Precondiciones:** El usuario debe tener una sesión activa en el sistema.
* **Postcondiciones:** * La sesión del usuario es invalidada.
  * El usuario es redirigido a la pantalla de inicio de sesión.
  * No se puede acceder a funciones del sistema sin volver a autenticarse.

### Secuencia Normal
1. **Acción (Actor):** El usuario presiona el botón/opción 'Cerrar sesión'.
   * **Reacción (Sistema):** El sistema muestra un mensaje de confirmación: '¿Está seguro que desea cerrar sesión?'.
2. **Acción (Actor):** El usuario confirma la acción.
   * **Reacción (Sistema):** El sistema invalida el token de sesión, limpia los datos de sesión almacenados y redirige al usuario a la pantalla de inicio de sesión.

### Excepciones
* **1. El usuario cancela la confirmación:**
  * **Reacción (Sistema):** El sistema cierra el diálogo y mantiene la sesión activa sin realizar ninguna acción.

### Requisitos No Funcionales y Atributos
* **Rendimiento:** El sistema deberá realizar el cierre de sesión (pasos 1 al 2) en un máximo de 2 segundos.
* **Frecuencia:** Se espera que se lleve a cabo una media de 1 vez por usuario por sesión.
* **Importancia:** Importante
* **Urgencia:** Hay presión
* **Comentarios:** El sistema debe asegurar que la sesión quede completamente invalidada en el servidor para evitar accesos no autorizados, incluso si el usuario cierra el navegador sin usar esta opción.

## CU-08: Crear solicitud
* **Descripción:** Un solicitante o administrador ingresa los datos necesarios para crear una solicitud de paquete. El sistema verifica automáticamente el stock disponible entre los remitentes y, de haber stock suficiente, aprueba la solicitud notificando al solicitante; de lo contrario, la rechaza indicando el motivo.
* **Actores:** Solicitante, Administrador (Actores secundarios: Sistema)
* **Precondiciones:** * El actor debe tener una sesión activa.
  * El solicitante debe tener cuenta activa y no estar baneado.
  * Debe existir al menos un remitente activo registrado en el sistema.
* **Postcondiciones:** * La solicitud queda registrada en estado Creada y luego Aprobada o Rechazada según el resultado del control de stock.
  * El solicitante recibe una notificación del resultado.
  * Si fue aprobada, la solicitud queda disponible para ser asignada a un remitente.

### Secuencia Normal
1. **Acción (Actor):** El actor accede al formulario de nueva solicitud.
   * **Reacción (Sistema):** El sistema muestra el formulario con los campos: zona/localidad de entrega, coordenada, tipo y cantidad de suministros solicitados.
2. **Acción (Actor):** El actor completa los datos del formulario y confirma la solicitud.
   * **Reacción (Sistema):** El sistema registra la solicitud en estado 'Creada' y ejecuta automáticamente el caso de uso **Controlar Solicitud** (CU-09) para verificar disponibilidad de stock.
     * **2.1 Si hay stock suficiente:** El sistema actualiza el estado a 'Aprobada', ejecuta Aprobar Solicitud y envía una notificación de aprobación al solicitante.
     * **2.2 Si no hay stock suficiente:** El sistema actualiza el estado a 'Rechazada', ejecuta Rechazar Solicitud y envía una notificación de rechazo al solicitante indicando qué stock falta.

### Excepciones
* **1. El actor no completa todos los campos obligatorios:**
  * **Reacción (Sistema):** El sistema deberá mostrar un mensaje de error indicando los campos faltantes y no procesará la solicitud.
* **2. La coordenada o zona ingresada no es válida o está fuera de cobertura:**
  * **Reacción (Sistema):** El sistema deberá informar al actor y solicitar una corrección.

### Requisitos No Funcionales y Atributos
* **Rendimiento:** El sistema deberá realizar el control de stock y registrar el resultado (pasos 1 al 2) en un máximo de 5 segundos.
* **Frecuencia:** Se espera que se lleve a cabo una media de 10 a 50 veces por día dependiendo de la operación.
* **Importancia:** Vital
* **Urgencia:** Inmediatamente
* **Comentarios:** Este caso de uso es el núcleo funcional del sistema. Incluye los sub-casos Controlar Solicitud, Aprobar Solicitud y Rechazar Solicitud. Consulta pendiente: determinar si el sistema sugiere un remitente alternativo o cantidad ajustada cuando el stock es insuficiente.

## CU-09: Controlar solicitud
* **Descripción:** Permite al sistema verificar si una solicitud creada puede ser realizada, controlando la disponibilidad de stock entre los remitentes. En caso de haber stock suficiente, el sistema cambia el estado de la solicitud a “Aprobada”. Opcionalmente, puede asignar un remitente automáticamente y pasar la solicitud a “Asignada”. En caso contrario (stock insuficiente), la solicitud cambia a estado “Rechazada”.
* **Actores:** Sistema
* **Precondiciones:** * Debe existir en el sistema una solicitud en estado “Creada”.
  * El sistema debe tener acceso al stock de los remitentes.
* **Postcondiciones:** * Si existe stock suficiente, la solicitud pasa al estado “Aprobada”. Opcionalmente puede asignarse un remitente y pasar a “Asignada”.
  * Si no existe stock suficiente, la solicitud pasa al estado “Rechazada”.
  * Se notificará al solicitante del resultado de la verificación.

### Secuencia Normal
1. **Acción (Actor):** El sistema detecta la creación de la solicitud.
   * **Reacción (Sistema):** El sistema consulta el stock disponible de los remitentes y verifica si es posible cumplir la solicitud.
   * *Nota:* **1.1** Si no hay stock suficiente, el sistema cambia el estado de la solicitud a “Rechazada” y notifica el rechazo al solicitante.
   * *Nota:* **1.2** Si hay stock suficiente, el sistema cambia el estado de la solicitud a “Aprobada” y notifica la aprobación al solicitante.
2. **Reacción (Sistema):** (Opcional, si se asigna remitente automáticamente) El sistema selecciona un remitente disponible.
3. **Reacción (Sistema):** El sistema asigna el remitente a la solicitud.
4. **Reacción (Sistema):** El sistema cambia el estado de la solicitud a “Asignada”.
5. **Reacción (Sistema):** El sistema notifica la asignación de la solicitud al solicitante y al remitente.

### Excepciones
* *No se registraron excepciones para este caso de uso.*

### Requisitos No Funcionales y Atributos
* **Rendimiento:** El sistema deberá realizar el control en un máximo de 5 segundos, con posibles aumentos en momentos de mucho tráfico.
* **Frecuencia:** Este caso de uso se espera que se lleve a cabo a diario de manera masiva.
* **Importancia:** Vital
* **Urgencia:** Hay presión
* **Comentarios:** -

## CU-10: Cancelar Solicitud
* **Descripción:** El solicitante o el administrador cancelan una solicitud existente mientras esta aún no ha sido enviada. El sistema actualiza el estado de la solicitud y notifica al remitente asignado (si lo hubiera).
* **Actores:** Solicitante (Actor principal), Administrador (Actor secundario), Sistema
* **Precondiciones:** 1. El usuario ha iniciado sesión.
  2. La solicitud existe en el sistema con estado Creada, Aprobada o Asignada.
  3. Si el actor es Solicitante, la solicitud le debe pertenecer.
* **Postcondiciones:** 1. La solicitud queda en estado Cancelada.
  2. Se libera el stock comprometido (si aplica).
  3. El remitente asignado recibe notificación de cancelación.
  4. El sistema registra fecha y motivo de cancelación.

### Secuencia Normal
1. **Acción (Actor):** El usuario ingresa al listado de sus solicitudes y selecciona la solicitud que desea cancelar.
   * **Reacción (Sistema):** El sistema muestra el detalle de la solicitud con sus datos y estado actual.
2. **Acción (Actor):** El usuario hace clic en la opción «Cancelar solicitud» e ingresa (opcionalmente) un motivo de cancelación.
   * **Reacción (Sistema):** El sistema verifica que la solicitud tenga un estado que permita cancelación (Creada, Aprobada, Asignada).
3. **Reacción (Sistema):** El sistema actualiza el estado de la solicitud a Cancelada y registra fecha, hora y motivo.
4. **Reacción (Sistema):** El sistema libera el stock comprometido del remitente correspondiente (si la solicitud tenía un remitente asignado).
5. **Reacción (Sistema):** El sistema envía una notificación al remitente asignado (si existe) informando la cancelación.
6. **Reacción (Sistema):** El sistema muestra un mensaje de confirmación al usuario indicando que la solicitud fue cancelada exitosamente.

### Excepciones
* **E1. El usuario intenta cancelar una solicitud en un estado que no lo permite (Rechazada, En Preparación, Listo, En Camino, Lanzada, Completada, Cancelada o Anulada):**
  * **Reacción (Sistema):** El sistema muestra un mensaje de error indicando que la solicitud no puede cancelarse en su estado actual y no realiza ningún cambio.
* **E2. La sesión del usuario expira durante la operación:**
  * **Reacción (Sistema):** El sistema descarta la operación, mantiene el estado anterior de la solicitud e informa al usuario que su sesión ha expirado.

### Requisitos No Funcionales y Atributos
* **Rendimiento:** El sistema deberá realizar las acciones descritas en los pasos 3 al 5 en un máximo de 3 segundos.
* **Frecuencia:** Se espera que este caso de uso se lleve a cabo una media de 5 a 20 veces al día.
* **Importancia:** Importante
* **Urgencia:** Hay presión
* **Comentarios:** -
